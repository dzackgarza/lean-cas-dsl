# Revision-bound controller construction

This is reviewable controller source, not an accepted controller release. The protected
launcher supplies the obligation, role, protected requirements and judging inputs, and
independently supplied task. Authors receive only their role's assigned immutable inputs
and source read/write/list, immutable submission and configured focused validation tools.
`launch_author.py` starts a fresh Claude Code session with those sole MCP capabilities,
empty built-in tools and disabled ambient settings. This does not restrict existing shared
construction sessions or claim an operating-system directory boundary.

`launcher.py` checks canonical paths and rejects protected controller, judging, policy and
acceptance paths for ordinary kernel authors, symlink aliases, hardlinks and nonregular
files. Its fixed Git operations can checkpoint permitted edits without exposing shell or
Git commands. Acceptance authors can submit independently authored `tests/acceptance/`
questions and interpretations. The standalone read-only source-envelope endpoint is:

```sh
python3 custodian/controller.py submit-acceptance --repository /workspace/lean-cas-dsl --candidate <full-commit>
```

At each materialization, author-server start and independent assessment invocation,
`dependencies.py` fetches `refs/heads/main` for configured mathematics, contract, leaves
and notebook source dependencies consumed by that operation. Author startup resolves only
its role's assigned inputs and the provenance dependencies of its public artifact; an
unavailable unrelated source or stale unconsumed artifact does not block the role. Complete
independent assessment still resolves and checks the complete tuple it reviews.
Their configured commits are previous snapshots, never
pins or admission requirements. The trusted configured URL (or protected input storage's
origin) supplies the remote; no author tool chooses it. A matching mutable source base
also starts from that resolved dependency revision. Requirements, acceptance/judging
source, signing identities and public artifact bytes remain independently fixed.
`materialize.py` prints its resolved configuration; author startup records only its
permitted input revision snapshot on stderr. Independent assessment saves
`resolved-configuration.json` beside the exact request. Capture those outputs as run
records. Both committed and external public artifacts require exact mathematics AND contract
provenance. Missing provenance or either stale source identity blocks the artifact's
consumer; resolution never relabels or regenerates it.

Submission grants no acceptance. `controller.py` constructs the complete immutable tuple,
unchanged source, patches and governing requirements. Independent review must bind that
exact request and independently configured judging base with the configured SSH identity. Altered context,
stale bases, invented source attached to real revision IDs and candidate self-admission
fail. Committed and externally materialized public metadata carry source revision, complete
content digest and contract provenance; leaf authors receive that frozen public artifact
and contract, without acceptance internals or upstream source.

`execution.py` runs candidate validation in an immutable Docker image with no network,
authority environment, Git database, host socket or writable source. Streaming output is
bounded and a named container is forcibly removed after success, failure, output overflow
or timeout. These outcomes report operational failures, not mathematical invalidity.
`prepare_runtime.py` creates a minimal validation image from an installed system Python;
it does not supply a CAS acceptance evaluator.

`authority_review.py` uses the existing reviewer subscription and signing identity. The
review receives one complete snapshot; large snapshots remain available through scoped
Read, Glob and Grep in that same continuing review, with no commands or candidate execution.
Identical signed discussions are reused from the existing `custodian/rejections` history.
Reconsideration requires new evidence in that discussion. An invocation failure produces
no judgment. `record_review.py` verifies signatures before persisting that discussion.
`apply_assessment.py` assembles the proposed next configuration; `publish_assessment.py`
replays source dependency commits from that signed request without fetching newer main,
and verifies the unchanged protected inputs and independent signature before emitting a
publication proposal. Its explicit `--publish` operation opens a conventional
protected-reference PR. Neither operation bypasses independent admission or claims B0
completion. Fixture model responses and ephemeral fixture keys test wiring only.

The authority workflow runs only from `accepted/controller`, reads candidate commits as
Git data and keeps reviewer credentials out of candidate validation. The source workflow
runs Python checks, actual Docker isolation probes and all existing 70 custodian fixtures
without those authority credentials. See [SETUP.md](SETUP.md) for concrete deployment.
