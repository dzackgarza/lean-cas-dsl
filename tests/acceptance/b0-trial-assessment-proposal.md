# Mathematical assessment preparation for the fixed B0 exit trials

This specifies how to assess the existing ten mechanisms in the B0 plan. It is
an acceptance proposal, not a new policy or additional completion denominator.
Concrete extensions will be chosen independently **after** the kernel, contract
and old leaves are frozen. No extension is selected here, and no trial is claimed
to have executed. Mathematical inputs are the accepted `lean_categories`
`b249ca2`, the approved SPEC, and the owner's fixed B0 requirements.

For each trial the actual frozen revision identities must be attached to the
observation. An independently justified question is fixed before its computation.
Original semantic objects, maps, parameters and old source revisions remain
identifiable. Merely obtaining the desired number is insufficient where the
required result includes a map or chosen structure.

## New structured object

The independent contributor supplies its mathematical object and selected data
under the accepted mathematical extension interface. Applicability of existing
operations is justified by the object's actual structural functors. When two
objects have the same carrier, their differing chosen data must remain visible
in both operand identity and request identity. The observation must demonstrate
an inherited operation through the structural route, and distinguish the two
selected objects even if that operation happens to return the same value.
Carrier cardinality alone cannot distinguish forms on that carrier.

## New generic operation

The independent contributor specifies a total mathematical operation on its
declared domain, with parameter dependence and result form. Existing applicable
objects are then observed to acquire the operation from their unchanged accepted
definitions. Mathematical applicability is established from the domain and
structural path before looking for execution. Both an applicable existing object
and an outside-domain argument are necessary observations already required by
generic application: the latter cannot become valid through backend availability.
Absence of an implementation is distinct from absence of the operation.

## Generic group-valued construction

The constructed object's group structure must be the one carried by its
construction. The inverse has to belong to that selected group and satisfy its
identity equations, rather than be an inverse in an incidentally shared carrier.
A subgroup result includes a monomorphism into its actual ambient group.
An automorphism result includes composition of actual automorphisms of the
selected object, with its original parameters. A stabilizer result includes its
inclusion in the ambient automorphism group. The applicable inherited group and
subgroup operations must follow from these data without an object-specific row.

## Classifier/refinement

For a host object X and classifier P, the refined object is (X,p) with
p:P(X). Forgetting this proof returns the same X with its original defining
data. The acceptance question distinguishes a proof-bearing refinement from
a Boolean property observation. A computational answer about P(X) supplies
a value to compare; it cannot itself construct p or move X into a new host.
An applicable operation on the refined host must retain the chosen proof-bearing
datum and any remaining parameters. The mathematical justification is the full
subcategory construction, not a backend's classification of an object.

## Competing structural routes

Write F and G for the two actual composite functors from the source host to
the target. Retain the edges of each composite in the semantic question. In
the absence of an admitted identification, there are two routes and an
ambiguity; the observation names both. With an admitted invertible comparison
alpha:F ≅ G, the question retains alpha, its component at the actual source
object, and the route to which it compares. Neither source declaration order
nor realization availability can supply alpha. Equal backend values cannot
establish the comparison, and equal carriers cannot merge selected structures.

## Parameter/base transport

For a map u:b' → b in the registered base category and an object X over b,
the observed result is the prescribed u*X over b', with its cartesian map
u*X → X lying over u. Both the base arrow and the lifted arrow are retained.
The cartesian property says that any arrow into X whose base map factors
through u factors uniquely through that lifted arrow. This identifies the
reindexed object through the given fibration, not through a shared display name.
For scalar restriction along a ring homomorphism R → S, the R-action on an
S-module is r·x=u(r)·x; copying the S-action or forgetting the ring map changes
the question. For base change, the tensor-product parameters and comparison
maps are retained. Which construction applies is decided by the accepted
mathematical interface of the independently chosen extension.

## Nonidentity presentation change

Retain two presentations P and Q and the accepted comparison phi:P ≅ Q.
The question about transport of a:P is about phi(a):Q. It is not about a=phi(a)
in a common carrier, nor about equality of the two presentations. The expected
value is established by independently applying the actual nonidentity map.
The inverse and its equations establish the comparison; correspondence of
opaque backend labels does not. At least one datum must distinguish this map
from an identity or accidental copying of a presentation generator. The fixed
F₉ calculations in `b0-required-positive-proposal.md` already illustrate the
mathematical distinction, but do not choose the independent exit extension.

## Structured result lifting

For a formed-module map f:V → V' with selected value module W and bilinear
forms B and B', the lifted module kernel retains

- the actual submodule K=ker(f), not an abstract isomorphic module;
- its inclusion i:K ↪ V and the equation f i=0;
- the selected base ring R and value module W;
- the restricted form B_K(k,l)=B(i(k),i(l));
- the lifted inclusion, whose form-preservation equation uses this B_K;
- the specified comparison between the underlying lifted carrier and the
  module-kernel result.

The mathematical justification of the restriction is independent of any
computation: bilinearity of B_K follows by composing B with i in both arguments.
For a form-preserving map h:T → V with f h=0, the unique module factorization
through i preserves forms since i composed with that factorization is h.
Thus the retained inclusion and restricted form determine the lift. This is
the accepted `formedKernel_pairing`/`forgetMonoLift` meaning in `b249ca2`.
The result's value module is W even when its carrier is the zero module.

The accepted source differentiates fixed-value `BilinModuleCat R W` from
varying-value `BilWFormCat R`. The named A/A_dual/to_dual objects use the latter;
the registered kernel restriction lift in the accepted source uses the former.
A trial cannot replace one host with the other without an accepted mathematical
construction applying to the actual input. Missing lift computation must be
reported as a named gap. It does not satisfy the required positive execution.

## Generic application/admission/binder

The independently chosen instance has an independently specified dependent
signature, its actual parameters and declared evidence obligations. Every
argument is checked at that signature. Admission retains the original datum
and evidence of the stated condition; an unassigned metavariable is not data.
Binding is interpreted using the admitted binder's mathematical action on the
body and domain. Bound-variable renaming preserves that mathematical body;
changing the domain, binding scope or body changes the question. A new instance
has to use this path without an operation-specific kernel case. Successful
evidence discharge must establish the upstream mathematical obligation rather
than a statement about the reader's temporary representation.

## Leaf replacement

For each already fixed semantic question, record its type, meaning, available
operations and retained maps before execution. Compare these same observations
with no leaves and after replacing the computational realizations. Semantic
invalidity, ambiguity, missing implementation, unavailable execution, malformed
results, wrong values and internal errors remain distinct as prescribed by the
controlling outcome interface. Successful assertions are separately reported.

Expected mathematical answers stay fixed. Missing realization changes execution
availability, an unavailable engine changes execution outcome, a malformed result
fails decoding, and a well-formed incorrect value fails comparison. None changes
the question, its type or applicability. A runtime exception cannot establish
mathematical invalidity. The observations must come from the actual invocation
and response path; a leaf's claim that it ran or that its result is trustworthy
is not an observation of that path.

## What remains to execute

This preparation supplies mathematical assessment conditions for every existing
exit mechanism. Independent concrete choices, accepted extension releases and
actual trial invocations remain future inputs. An edit required in the frozen
kernel or old leaf makes the affected trial fail; its generic deficiency is
repaired before a new frozen tuple is assessed. Positive execution, question
preservation and the compositional arguments are separate obligations throughout.
