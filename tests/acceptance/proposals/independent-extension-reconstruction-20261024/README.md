# Independent reconstruction of extension acceptance proposals

**Status: independently reconstructed proposals, not recovered original source and not admitted acceptance.**

The unpublished extension proposal files from the earlier container are unavailable. The retained
assignment fixes ten mathematical trial scopes and a separate two-stage formed-arrow example;
it does not preserve an original assertion inventory or all original assertion bytes. This directory
therefore assigns new local proposal labels `RX-01` through `RX-10` and `RX-LIFT`. Those labels do
not identify, replace, or migrate any previously admitted assertion.

The author used the assigned mathematical source checkout, its declarations and proofs, the
public `SPEC.md`, and the public contract documentation only. No kernel implementation, leaf,
leaf answer, runtime trial report, or engineering failure was used to select a proposition or an
expected answer. No Lean build, leaf execution, or permanent suite was run by this author.

## Deliverables

- [questions.md](questions.md) fixes the complete mathematical questions, selected data, maps,
  expected formulas, and exact remaining public-surface obligations.
- [source-notes.md](source-notes.md) gives declaration-level mathematical citations and independent
  derivations of the numerical and formula expectations.
- [observation-controls.md](observation-controls.md) separates the registration-order,
  missing-comparison, failure-stratification, and session-ownership observations from the
  mathematical assertions they must preserve.
- [surface-extracts.cas.proposal](surface-extracts.cas.proposal) contains the portions expressible
  using documented surface forms and registered names without inventing a new notation. Its suffix
  is deliberate: it is a proposal excerpt, not a suite file and not complete trial coverage.
- [public-surface-status.md](public-surface-status.md) records the additional public construction,
  component and lift syntax supplied during reconstruction, and the remaining exact term/observer
  obligations.
- [provenance.json](provenance.json) identifies the source revisions and exact files inspected.
  Digests are reproducibility data, not admission or interpretation authority.

All files in this change are additive and confined to this directory. Existing assertions,
expected values, inventories, protected baselines, and admission/interpretation records are not
edited. Source integration, a commit, or a later successful execution does not self-admit these
proposals or approve a baseline migration.

## Required execution and interpretation

The eventual trials must ask the stated questions through the public mathematical language and
reuse actual computed objects and maps wherever the question specifies successive computations.
Proofs here establish expected mathematics; they are not a substitute for required execution.
Conversely, a returned answer, success label, certificate, or proof claim establishes no
mathematics and supplies no admission evidence.

Finite displayed observations accompany complete functions and universal equations. They do not
replace them. A trial which obtains the displayed number while omitting the selected coefficient
map, an inverse comparison, the original generalized domain, a returned defining map, or the
second lift is incomplete.

Before a future frozen execution is counted, the independent acceptance process must establish
the interpretation of the complete questions and the appropriate observation controls. This
directory neither declares a mathematical release accepted nor approves any interpretation
migration. In particular, it cannot establish identity with the lost proposals.
