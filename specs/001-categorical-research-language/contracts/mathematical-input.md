The local boundary below applies the constitution to this contract. Mathematical declarations remain owned by the independent formal source.

## Required source boundary

Under [C23](../../../.specify/memory/constitution.md), preparation consumes the checked context,
term, category, parameters, selected structures and required comparisons. It resolves each
operation at its actual formal domain, including core groupoids and dependent or higher domains.
The accepted functorial route is part of the meaning; parallel endpoints do not identify routes.
Refinement consumes an upstream classifier rule and evidence, retaining any selected fiber data.

The output fixes the operation, dependent input and result interfaces, selected endpoints and
comparison transports. Ordinary, deferred and provider-requested public calls use this same
boundary. A missing formal declaration is distinct from missing computation of a valid request.
See MM001, MM003–MM006 and MM010 in the [specification](../spec.md#mathematical-model-acceptance).

## Fixed results and independently declared choices

A fixed-result request keeps the result prescribed by its accepted mathematical declaration.
A function defined using `Classical.choice` is still that fixed function; its implementation
does not thereby gain permission to return an arbitrary candidate of the same Lean type.

A permitted-choice request requires the independently accepted candidate family, admissibility
condition and dependent continuation, with the required suppliers and availability stages.
Preparation retains those declared boundaries and the actual chosen data through later uses.
A result type, a runtime supplier tag or a successful computation cannot supply missing choice
authority. Missing accepted input remains an unfulfilled requirement under
[C1, C9 and C10](../../../.specify/memory/constitution.md#independent-authorship-and-permitted-inputs-c1-c9-c10);
a kernel author cannot author, commission or prescribe its upstream mathematical repair.
