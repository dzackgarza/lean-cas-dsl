The phase records the exact legacy source/binary and runtime library selection, and runs it only during this explicit validation. Its adapter must capture the legacy ready announcement and report **zero executable source transmissions** for both inspect and execution refusal. It records `pass`, `fail` or `environment_error`; skipped, unrun or incomplete observations cannot pass. Exit 0 means every prescribed lifecycle expectation was observed; exit 1 means a violated expectation; exit 2 means a missing/incompatible validation environment. The final verification writes `candidate-final-summary.json` without replacing the initial successful build receipt. Neither record substitutes for independent mathematical assessment.

| Required observation | Evidence the new integrated check must retain |
|---|---|
| Inspect/complete before execution, after cancellation, and after worker death | No executable cell request, no bootstrap/replay, no dispatch, unchanged committed context; capability/version mismatch is explicit. |
| Two waiters for one occurrence | At most one dispatch, both waiters join the same pending outcome, and selection/context remain identical. |
| Explicit rerun | New occurrence identity; no automatic retry of the prior occurrence. |
| Cancellation before send, during send, after response, and before commit | Correct consumption state, no late publication, no overwritten committed state, retained original failure/indeterminate status. |
| Normal Jupyter interrupt / cooperative cancellation | Stop new child/resume scheduling and publication; drain each exact outstanding frame before releasing its connection permit; preserve earlier committed values of the still-live owner. A missing reply or unacknowledged cancellation is reported, with no automatic grace-period kill or owner replacement. |
| Explicit force cancellation or actual framing/transport loss | Close and report the exact `invalidated_owners`; dependent old references become unavailable while unrelated portable data and live owners remain usable. Never describe forced owner loss as successful cooperative preservation. |
| Worker/process generation change | Stale owner/capability fails before dispatch; no reconstruction from a carrier label or leaked cross-generation handle. |
| Failed cell after earlier effects | No partial mathematical publication; consumed occurrences remain consumed outside rollbackable snapshots. |
| Multiple/zero realizations | Complete semantic candidate/ambiguity behavior with no provider probing and no implicit fallback. |
| Returned structured values | Actual selected data, maps, full callable interfaces, and required later uses survive in the same intended owner scopes, including nonidentity transport and dependent results. |
| Display protocol | One mathematical LaTeX display event per result, useful text fallback and actual qualifications; diagnostics remain separately available. |

The retained `ci_operation_owner_control.py` is a historical comparison tool with hard-coded old `Realize` modules, frozen probe hashes, a baseline kernel tree, and a reviewed old contract override. It is not the new lifecycle runner, and the new plan must not infer notebook safety, arbitrary-input liveness, complete portability, or mathematical correctness from those historical controls.

After the entire fixed V1 combination, full timing checks, actual notebook, new lifecycle checks, and independent assessments succeed together, freeze the whole source/contract/compiler/runtime/consumer/build/engine/assessment baseline. Only then conduct both independently chosen contribution directions through the actual public surface. This plan chooses **no** new leaf or mathematics specimen. No core, contract, consumer, or oracle accommodation is allowed during a trial. A necessary repair requires a new whole-baseline freeze and a fresh contributor choice, while preserving the complete fixed denominator. No shell loop retries failed provider effects.

V1 completion is the conjunction of all assigned requirements and independent assessment, not an accumulation of partial passing scripts. Full B0 and broad Sage parity retain their separate later completion boundaries. The [resolution addendum][resolution] supplies the scoped current-source finite-enclosure, first-hit and comparison argument, and separates partial correctness, conditional progress and actual delivery.
