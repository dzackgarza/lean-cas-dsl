## Execution order

The unchecked tasks are executed in the order of this document. The first unchecked task is the active task. Other work must serve the active task.

`After` names the inputs that a task needs for completion. It does not postpone the removal of a recovery path whose consumer has moved.

**An upstream dependency is a task (constitution C21).** When a task needs a mathematical declaration that lean-categories does not have, this file holds a task before it that supplies the declaration. That task names the lean-categories issue. Do it in lean-categories as a formalization author under that repository's rules: from the mathematics and its sources, at its own generality, not shaped to the kernel. Then return to the consumer. [Upstream inputs and their tasks](#upstream-inputs-recorded-as-missing) lists every known input with its task. An input that is found later gets its lean-categories issue and its task in the change that records it; no input waits for its consumer.

A wait on an environment that is not available blocks only the work that needs it (constitution C16). Complete the parts that do not need it and continue with the next unchecked task whose `After` inputs are present. The waiting task keeps its position and its checkbox.

**Kernel work and leaf work (constitution C22).** Every task of Part 1 is kernel work, except the lean-categories tasks T118 to T125 and T128 to T138 (formalization work, owner M) and the feedback tasks of Phase 0. In Part 2, T133 and T225 to T234 are lean-categories tasks too. The checks of kernel work observe what the kernel does: the selected reading, the prepared request with its operation address and operands, the dispatch, the admission of the reply, the retained value and its later use, and the outcome when no leaf is registered. They use a protocol peer or an empty manifest. No Part 1 task, no checkpoint and not F requires a mathematically correct computed value. Such a value needs an implementation of every category on the selected structural route (for `2 * 3 = 6 in ℤ`: from sets up to rings). It belongs to the [computational milestones](plan.md#computational-milestones). A phase that is named for a user story completes the kernel work for the forms of that story; the story is accepted with computed results (spec, session 2026-11-25).

All functional tasks include the actual type/domain/selection/data/lifetime checks necessary for their behavior. C21 does not waive those checks. **Roles:** K = kernel/contract engineering; I = integration; A = independent assessment; L = separately situated public-only computational contributor; M = independently authorized mathematical author.
