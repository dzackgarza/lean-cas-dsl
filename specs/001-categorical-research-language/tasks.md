## Execution order

The unchecked tasks are executed in the order of this document. The first unchecked task is the active task. Other work must serve the active task.

`After` names the inputs that a task needs for completion. It does not postpone the removal of a recovery path whose consumer has moved.

A wait blocks only the work that needs the missing input (constitution C16). When the active task, or a part of it, waits on an input that its role must not supply, or on an environment that is not available, do the following:

- complete the parts of the task that do not need the input;
- record the missing input at its owner;
- continue with the next unchecked task whose `After` inputs are present.

The waiting task keeps its position and its checkbox.

A change of order is an edit of this file. The commit states the reason.
