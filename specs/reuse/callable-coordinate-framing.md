## Owner

Mathlib owns categorical Hom types, composition, functor actions and endpoint
comparisons. The accepted catalogue supplies every selected category, structure,
numeral owner and structural action. `CategoryContext.checkMorphism` checks the
complete dictionary and original endpoints. `presentMorphism` consumes the
already accepted endpoint comparisons. `CasContract.Port` owns the existing
`typedMap`, `element` and `pointView` formats. No new mathematical definition,
registration, comparison or public encoding is introduced.

`lean-categories` also owns the extent of a subset and its finite-subset literal
denotation. The public contract already releases
`extent(powerObjectId, ambientObject, subsetData)` and
`finiteData(objectDescriptor, pointInventory)`. The registered `Finset` literal
uses the existing list-of-members codec. The kernel does not add a subset
definition, construct a membership proof, or equate a computed extent with the
independently retained formal object.

## New code

An arithmetic owner can differ from the complete coordinate in which its point
was independently read. A symbolic `element` descriptor retains that owner; it
cannot replace the complete intermediate coordinate of a later composition.
Callable framing now retains a closed symbolic element's checked source and
target in the public `typedMap` frame. The original scalar-owner data remain
inside it, including every opaque owner and accepted endpoint presentation.
Already self-contained symbolic maps and opaque callables keep their data.

Closed product components that are symbolic elements receive the same framing.
The ordered product-point array and already returned component data keep their
existing representation. A framing flag records presentations already applied;
it does not exempt the formal callable from a subsequent full endpoint check.

`CallableCoordinateFramingProbes` checks symbolic and owned whole maps, exact
middle endpoints, distinct complete structures with the same carrier, literals
whose scalar owner differs from their coordinate, and retained returned owners.
Existing product-point and presentation probes remain unchanged. The unchanged
RX10 input and six required outcomes are a separate engineering execution scope;
neither compilation nor an arbitrary token supplies a mathematical answer.

Portable extents now pass through the same typed object boundary as named
objects and products. The validator checks the registered power-object id, the
complete actual ambient interface, and the published subset-literal data
schema. Its interface expression contains a fresh typed subset placeholder;
returned members never become a formal denotation. Finite keys come only from
the actual registered finite-subset representation, with duplicate keys
rejected, and a `finiteData` inventory must describe that same representation.
A well-framed wrong subset remains a computation for independent acceptance.

Transparent `finiteData` and `objectPresentation` wrappers inherit selection
syntax only from their enclosed descriptor. An anonymous extent does not select
a formal receiver. Its use as an action source requires the independently
retained complete input binding, including the selected category and action.

`PortableExtentDataProbes` checks the actual portable object and whole-map
interfaces, wrong-but-well-framed computed values, invalid ambient points,
unknown power objects, duplicate or incomplete inventories, and retained versus
unbound anonymous action inputs. These are generic framing controls, not a new
mathematical acceptance suite. The frozen independent source/target leaf trial
remains a separate process execution obligation, with its original failed run
preserved.
